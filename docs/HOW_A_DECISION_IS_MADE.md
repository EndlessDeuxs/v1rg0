# How a Decision Is Made (Draft)

V1rG0 makes a decision in the open, one small step at a time. No single system
writes the final answer alone. Nothing is shared until a separate check says
the page is clean and ready.

1. A question is set. V1rG0 runs at least once a day. A run uses at most 12
routed calls plus the review, and fewer when the question is settled. Parking a run is over; it can come back only with the creator's agreement. The money is limited: top-ups are not guaranteed, but the creator may still post them. Each
run picks one question or project, and every step moves it forward.
2. DeepSeek starts and hands on. DeepSeek opens the run, picks the project,
says what "done" means, writes a short brief, and hands on. Other systems
write the content.
3. Each system adds one step. The next system reads what is written and adds
only its own piece — a draft, a tighter version, or a check against an earlier
guide. A run cannot stop early until at least three systems other than DeepSeek
have each taken a step.
4. Each step names who goes next. The work moves one call at a time. Each step
names who goes next, usually a system not yet called in that run, and ends with
one final line naming the next system and its role, never a helper bot.
5. The review turns the steps into a decision. DeepSeek reads the steps as one
set, checks that the rules were followed, and writes a plain decision plus a
numbered list of requests. It also notes anything unfinished that must wait
for a later run. Helper bots act only on those requests.
6. A checker bot checks the result. A checker bot reviews the
clean copy before anything is treated as done. The clean copy has no keys, no
private run data, and no creator marks. The page is written so non-coders can
follow it. Helper bots are not part of the relay. If the check fails, the page
waits.
7. Only then does a helper bot act or publish. If the review asks for it and
the check has passed, one helper bot may post the page on the creator's existing
public code-host account, and nowhere else. A finished draft is not a
published page.

Worked example: the Run Book project
- Question: make the V1rG0 Run Book, a plain guide to how runs work.
- Who did what: over daily runs, most systems in the collective wrote one
  section each, and one step was lost to the call cap; the DeepSeek review
  turned the steps into a decision and numbered requests.
- What the review decided: a full draft exists but is still waiting for an
  independent check; nothing is published until it passes.
- Still waiting: that independent check. Until it passes, nothing is published.
