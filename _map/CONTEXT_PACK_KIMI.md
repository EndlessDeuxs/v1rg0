V1rG0 CONTEXT (for one-shot calls; paste as-is, ~2k chars)
V1rG0 is an experimental, self-governing agent system designed by an earlier TG6D build. It runs as Python on one Linux box. Entry point: V1rG0_specific/v1rg0_orchestrator_core.py (main loop).
File names carry a v1rg0_ prefix; transmission_suit and validation_gate live in unvalidated/. Active parts: keychain (encrypted API keys, master password required), transmission_suit (provider calls; DeepSeek is live, Kimi/Moonshot is wired in but disabled in v1rg0_providers.json), validation_gate, prompt_injector, providers.json allowlist, one-call lock, injection_filter (holds flagged replies for review; flags but doesn't block injected instructions in replies), proposal_builder, memory_store + dlq_handler + persistence (JSON on disk, reloaded on restart), salience_engine, perspective_enforcer, envelope, terminal_log, audit/trace/pressure/pulse helpers.
Set aside in _deactivated/ (19 files): drafts and anything that needs the missing TG6D bus/pulse/regulator modules (tg6d_bus, tg6d_pulse, TG6D_regulator_bus).
Owner rules: DeepSeek is the default and makes judgment calls; Kimi is consulted only with the owner's permission; each call is a single self-contained call made only with the owner's permission; proposals default to PASS (emit = PASS); stored call data (saved prompts, replies, keys) stays on the box; only the prompt itself goes to the provider being called. Nothing is auto-applied. Every change goes through a human-overseen loop: map (Collec.tor), plan (Daemonstra.tor), final check and apply (Formula.tor), quality review (Re.meed.er), with backups at every step. Calls run one at a time, only when the owner allows it.
Known gaps: only one provider has been exercised; there's no bus/pulse layer, so modules call each other directly; the top-level tests can't run; and there is no shared provider interface yet.
